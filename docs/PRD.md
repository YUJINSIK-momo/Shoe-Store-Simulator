# PRD — Product Requirements

> **목적**: Claude가 작업 범위를 벗어나지 않도록 잡아주는 닻.
> 한 페이지 분량으로 유지한다. 자세한 사양은 별도 문서로.

---

## 1. 타겟 사용자

- **주 사용자**: 자신만의 신발을 디자인하고 싶은 20–30대 모바일 사용자 (스니커즈/패션 관심층)
- **부 사용자**: 한정판·커스텀 제작을 의뢰하려는 소규모 브랜드·셀러

## 2. 핵심 문제

기성 신발은 색상·소재 조합이 고정되어 있어, 사용자가 "내 취향대로" 만든 결과를 사보기 전에 확인할 방법이 없다.
→ **앱에서 부위별로 색상·소재를 바꿔 실시간으로 미리 보고, 그대로 주문**할 수 있게 한다.

## 3. 핵심 기능 (5개 이내)

- [x] **부위별 커스터마이징** — 갑피·밑창·안창·끈·로고의 색상/소재를 선택 (`customizeStore`)
- [x] **실시간 미리보기** — 선택 결과가 신발 뷰어(다각도 이미지 + 색상 뱃지)에 즉시 반영 (`ShoeViewer`)
- [ ] **디자인 저장/불러오기** — 만든 커스텀을 Supabase에 저장하고 갤러리에서 재주문
- [ ] **장바구니 → 결제** — 사이즈·수량 선택 후 토스페이먼츠/Stripe로 결제 (`cartStore`, UI 골격 완료)
- [ ] **주문 추적** — 주문접수 → 제작중 → 배송중 → 완료 타임라인

## 4. 비기능 요구사항

- **플랫폼**: iOS 우선 (TestFlight 베타), Expo SDK 54 / React Native 0.81
- **상태**: 로컬 상태는 Zustand, 서버 상태는 TanStack Query
- **보안**: 시크릿 키는 앱에 포함하지 않는다 (`EXPO_PUBLIC_` 공개키만). 결제 승인은 백엔드에서만.
- **성능**: 색상/소재 변경 → 미리보기 반영이 한 프레임 내 체감되도록 (재렌더 최소화)
- **배포**: EAS Build → TestFlight, main push 시 GitHub Actions 자동 빌드

## 5. 성공 기준 (측정 가능한 지표)

- 사용자가 앱 진입 후 **1분 내에** 신발 한 켤레의 색상/소재 커스텀을 완성한다
- 커스텀 → 장바구니 → 결제 진입까지 **이탈 없이** 도달한다
- TestFlight 베타 빌드가 정상 배포되어 테스터가 설치·실행할 수 있다

## 6. 범위 외 (NOT-DO)

이번 단계에서 **하지 않을** 것. 범위 폭주를 막는다.

- 3D 뷰어 (Three.js/Expo GL) — 2단계 이후. 현재는 2D 이미지/SVG 방식.
- 소셜 공유·커뮤니티 피드
- 다국어 (한국어 우선)
- 백엔드(NestJS) 실서비스 운영 — 현재 `api/`는 골격만, 백엔드는 별도 트랙
- Android 정식 대응 (코드는 호환되나 검증은 iOS 우선)
